# X-DeskTop 使用说明

> 面向使用者的操作手册。开发者向的架构与接口说明见 `README.md` 与 `docs/API.md`。

X-DeskTop 是一个 7×24 自主软件测试工厂控制台：导入需求后，5 个角色机器人接力完成
**测试方案（KEEL）→ 需求分析（ORACLE）→ 用例设计（WEAVE）→ 自动执行（SWARM）→ 缺陷定级（SENTRY）**
全流程，产物实时回流到用例库与缺陷库。

| 角色 | 代号 | 职责 |
| --- | --- | --- |
| T-01 | KEEL | 测试方案：拆解验收标准，输出范围/策略/准入准出 |
| T-02 | ORACLE | 需求分析：抽取测试点、澄清歧义、维护追溯矩阵 |
| T-03 | WEAVE | 用例设计：生成用例/数据/断言，维护优先级 |
| T-04 | SWARM | 自动执行：调度执行机池跑用例，失败自动重试 |
| T-05 | SENTRY | 缺陷定级：归并去重，输出 P0/P1/P2 与派单建议 |

---

## 1. 启动与访问

```bash
cd x-desktop
npm start            # 默认端口 8790
```

- 浏览器打开 **http://localhost:8790**
- 本系统**没有登录**：本地单机使用，打开即用；监听地址默认 `127.0.0.1`，仅本机可访问
- 停止：运行服务的终端 `Ctrl+C`（或结束 node 进程）
- 开发模式：`npm dev`（文件改动自动重启）
- 要求 Node ≥ 20，无任何 npm 依赖

**启动开关**：默认常驻线不自动运行（推荐试用方式）。若想启动即自动跑一轮演示数据：

```bash
AUTO_START=1 npm start
```

## 2. 配置真实模型（必做）

系统**只调用真实模型**，没有模拟模式。未配置时模型调用会失败并在日志中显式报错，流水线无法产出有效内容。

1. 复制环境变量模板并填写：

```bash
cp .env.example .env
```

```ini
LLM_BASE_URL=https://api.deepseek.com/v1   # OpenAI 兼容地址
LLM_API_KEY=sk-你的密钥
LLM_MODEL=                                  # 可留空：使用各角色绑定里配置的模型名
LLM_TIMEOUT_MS=30000
```

2. 重启 `npm start`，启动横幅显示 `模型 live · <地址>`，页面顶栏标签变为 **LIVE 模型**。

**常用供应商地址（均走 OpenAI 兼容协议）**：

| 供应商 | LLM_BASE_URL | 可用模型示例 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | deepseek-chat、deepseek-reasoner |
| OpenAI | `https://api.openai.com/v1` | gpt-4.1、gpt-4.1-mini |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | qwen3-max、qwen3-coder-plus |
| OpenRouter（聚合） | `https://openrouter.ai/api/v1` | 各家模型名均可路由 |
| 本地 vLLM / Ollama | `http://127.0.0.1:8000/v1` | 本地已拉起的模型名 |

3. 验证连通：进入 **模型** 页 → 对应供应商卡片 → **测试连接**，返回延迟即代表打通。

> 让不同角色真正用上不同厂商：把 `LLM_BASE_URL` 指向聚合网关（OpenRouter / one-api / LiteLLM），
> 各角色绑定里选各自模型名即可，无需改代码。

## 3. 界面导览（7 个页面）

| 页面 | 看什么 / 能做什么 |
| --- | --- |
| **总览** | 2.5D 流水线大屏：五阶段进度、机器人状态（点条目可暂停/恢复该机器人）、缺陷流、活动时间线、模块覆盖率、环境矩阵 |
| **需求库** | 需求卡片（状态：草稿/评审中/已确认/覆盖进度）；右上「**＋ 导入需求**」打开展开面板 |
| **用例库** | 全量用例表：优先级、归属需求、最近执行结果（pass/fail/skip）、耗时，可筛选 |
| **任务线** | 每批需求一条线（L-01、L-02…）：整线进度、四项指标、五角色实例标签（点标签＝暂停/恢复该实例的门禁）、并行度切换（1~4 线）、冻结整线 / 续跑 |
| **运行记录** | 每轮执行 RUN：进度条、通过/失败统计、终端式执行日志（含每次 LLM 调用记账与失败原因） |
| **缺陷库** | SENTRY 产出的缺陷列表：P0/P1/P2、状态流转（新建→已复现→修复中→已验证→已关闭） |
| **模型** | 供应商管理（启用/禁用、测试连接）、角色绑定（改模型/温度/预算）、实例级覆盖、上下文总线（共享上下文与压缩摘要）、「查看实际 Prompt」 |

## 4. 第一次试用（5 分钟）

前提：已完成第 2 节模型配置，数据为空白状态（见第 6 节）。

1. **导入需求**：进入 **需求库** → 「＋ 导入需求」→ 文本框粘贴需求，**每行一条**，格式：
   ```
   需求描述 | 所属模块 | 测试点数
   ```
   例如：
   ```
   订单支付回调需支持重复通知幂等 | order-payment | 6
   退款金额按分存储，展示按元换算 | settle-job | 4
   ```
   填写批次名（如 `release/4.3 · 回归`）→ 点「**解析并启动机器人**」。
2. **自动建线开跑**：系统解析需求后自动创建任务线并启动，五机器人按 KEEL→ORACLE→WEAVE→SWARM→SENTRY 接力。
3. **观察过程**：回 **总览** 看大屏动效与阶段推进；进 **运行记录** 看终端日志，每次模型调用都有
   `[LLM] 实例 → 模型 · in/out tok · 耗时` 记账，失败会显示 `失败: 原因`。
4. **查看产物**：**用例库** 出现 WEAVE 生成的用例；执行完成后 **缺陷库** 出现 SENTRY 定级的缺陷。
5. **收尾**：任务线状态变「done」后可在任务线页点「续跑」开启下一轮，或导入新需求再开一条线。

## 5. 日常操作

**多任务线并行**：每导入一批需求就多一条任务线；任务线页顶部「并行度」可切 1~4 线同时推进。
执行机池默认 8 台（`EXEC_POOL_CAP`），全局共享，占机/排队自动调度。

**暂停某个机器人（门禁）**：
- 总览页：点击 AGENTS 列表条目
- 任务线页：点击角色实例标签（如 `WEAVE·2`）
被暂停角色的阶段不再推进，恢复后继续。

**冻结 / 续跑**：任务线页对运行中的线「冻结整线」；对 done/paused 的线「续跑」。

**换模型**：模型页 → BINDING 表格改某角色的供应商/模型/温度；「设为覆盖」可让**某条任务线的某角色**单独用另一家模型（不影响全局绑定）；「清除覆盖」还原。改完立即生效，下一阶段调用即用新模型。

**共享上下文**：同一条任务线内所有角色读写同一份上下文总线（模型页可见），超过预算 55% 自动压缩为摘要——换了模型也不会丢失前序角色的工作结论。

## 6. 数据管理

所有业务数据存在 **`data/state.json`**（单文件 JSON，原子写入）。

| 命令 | 效果 |
| --- | --- |
| `npm run blank` | **全部清零**：需求/用例/任务线/运行/缺陷/日志/时间线/模型调用统计归零，只保留供应商与角色绑定配置（干净的试用起点） |
| `npm run reset` | 重置回**演示种子数据**（8 条示例需求 + 一轮历史执行 + 常驻回归线） |

- 备份：直接复制 `data/state.json` 即可
- 清空后重新试用：先 `npm run blank`，再重启 `npm start`（服务启动时读入内存并自动落盘，**清数据前需先停服务**）

## 7. 常见问题

**Q：启动后页面一直转圈 / 提示无法连接后端？**
服务没起来或端口被占用。`lsof -iTCP:8790` 查占用进程，或 `PORT=8899 npm start` 换端口。

**Q：流水线跑起来了但日志全是 `失败: 未配置 LLM_BASE_URL...`？**
模型没配置。按第 2 节填好 `.env` 后重启。

**Q：模型调用报 401 / 429？**
401＝密钥无效；429＝限流。去供应商控制台检查密钥与额度。

**Q：想让某个角色换模型试试效果？**
模型页 BINDING 改绑定，或用「实例覆盖」只改某条线的该角色。

**Q：演示数据太多想清空？**
停服务 → `npm run blank` → 重启。想要回演示数据用 `npm run reset`。

**Q：数据能多人共享吗？**
当前是单机单实例设计，无登录与多人协同。局域网共享需改监听 `HOST=0.0.0.0` 并自行加访问控制。

**Q：执行机池是什么？**
SWARM 跑用例的并发资源抽象（默认 8 台），只用于演示调度行为；真实执行需对接你自己的测试执行框架。
